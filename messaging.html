Owner Administration guide

Updated 24 October 2026 · Service administration

This guide belongs to the signed-in owner workspace. Owner access is separate from Head Teacher membership: an authorized, verified owner account does not need to register or join a school. A Firebase console login or a verified email alone does not grant this app role. Use your own authorized account and sign out on shared devices.

Use the existing six tabs below. Open a topic here for its workflow; closing this guide leaves your current tab in place.

1. Overview

Review service totals and use Refresh to reload them. School records can include test schools and incomplete registrations. Totals are not a count of paying customers.

2. Schools: identify, archive, restore or delete

Match the school name, unique School ID and linked Head Teacher before taking action. The registration filter distinguishes linked records from Needs review; Needs review means no matching active Head Teacher membership is linked. Repeated school names can have different IDs.

Search and filters apply to the current page. Use Previous page and Next page to inspect other pages. School status lets you choose active, archived or all statuses.

  1. Message school: opens the message controls with that active school selected. Check the school and recipient before confirming.
  2. Archive: review the school identity and confirm its ID. Archive retains records, licences and existing school access; it excludes the school from new service messages. It is not an access suspension.
  3. Restore: choose the archived status filter, find the school and confirm Restore. It returns to the active owner list and service-message recipients.
  4. Delete permanently: archive first. Review the deletion summary, confirm the exact School ID, type DELETE SCHOOL and acknowledge the backup/data-loss requirement. Use recent sign-in when requested.

Permanent deletion cannot be undone through SchoolHub. It removes the school’s cloud records, pupils, attendance, grades, fees, licences and school images, and unlinks staff. Their sign-in accounts are retained because an account can be used separately from that school. Arrange an appropriate backup first; the school core-record JSON export does not include every service record or cloud image.

Deletion runs as a cleanup job. Use Check deletion or Check last deletion for progress. Use Retry cleanup when offered if work remains. Do not interpret a started job as a completed deletion.

3. Messages & Push

Messages: choose one school, one eligible recipient, or the unarchived-school service audience. The service-wide audience covers active Head Teachers and teachers in unarchived schools. Enter a title and message, choose Review and send, read the audience and confirm only the intended recipients.

Wait for delivery status. An inbox count confirms saved messages, not displayed device alerts. If delivery is still processing, follow the retained request/status workflow instead of composing a new duplicate. School Head Teachers send only within their own school; this owner workspace has separate service permissions.

Push setup: use the public values from the SchoolHub Firebase project: Public Web Push key, Messaging sender ID and Firebase Web app ID. The public Web Push key comes from Cloud Messaging → Web Push certificates; the sender ID and app ID are in the web app configuration. Enable server push delivery and use Save push setup. These fields do not accept a service-account private key or a legacy server secret.

This device: choose message/activity preferences, enable push, and allow browser notifications. Each device must opt in separately. Refresh device status after changing permissions. Browser/phone restrictions, connectivity and notification settings affect delivery, including when the app is closed. In-app messages remain available without device push.

4. Licences

Review school licence status, expiry dates and report credits. Choose Live licences or Test licences deliberately; test entries do not represent real payments. Search applies to the current page. Use the page controls for other results. This view reviews service records; it does not collect a payment merely by opening it. Live app billing remains suspended in the current build.

5. Activity

Choose Messages, Push setup changes or School management, then Refresh as needed. Inspect the action, school/audience, actor and status. Use Previous page and Next page for older results. Message inbox totals confirm persisted delivery; they do not confirm an alert was displayed or read.

6. Account Security and sign-in problems

Open Account Security → Open Account Security for the owner account’s verification status and supported login email/password changes. Email/password accounts confirm the current password when requested. A new login email takes effect after verification. Google-only accounts manage credentials with Google. The app role stays with the account identity; changing a school contact address does not transfer owner permission.

If you see an access or verification error, check the signed-in account and its verification status. Sign out and back in after an authorized role change. If owner access cannot be confirmed, contact the service administrator; do not create a school as a workaround. No password, authentication token or service-account private key is needed in a support message.
